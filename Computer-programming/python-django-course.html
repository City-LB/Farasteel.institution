Chapter 1

Introduction to Python

Learning Objectives

By the end of this chapter, students should be able to:

  • Explain what Python is and why it is popular
  • Install Python and verify the installation
  • Run a simple Python program
  • Use the interactive Python shell (REPL)

1.1 What is Python?

Python is a high-level, interpreted, general-purpose programming language created by Guido van Rossum and first released in 1991. It emphasizes readability and simplicity. Python is widely used in web development, data science, automation, artificial intelligence, scientific computing, and scripting.

1.2 Why Learn Python?

  • Clear, readable syntax that is close to English
  • Huge standard library and ecosystem of third-party packages
  • Excellent for beginners yet powerful enough for professionals
  • Strong community and extensive documentation
  • Used by companies such as Google, Netflix, Instagram, Spotify, and NASA

1.3 Installing Python

Download the latest version from python.org. On most systems you can verify the installation with:

python --version
# or
python3 --version

1.4 Your First Program

print("Hello, World!")

Save the code in a file named hello.py and run it with python hello.py.

1.5 The Interactive Shell (REPL)

You can also type Python code interactively. Open a terminal and type python (or python3). You will see the >>> prompt where you can experiment freely.

Chapter Summary

  • Python is a readable, versatile programming language
  • Installation is straightforward from python.org
  • You can run scripts or use the interactive shell

2.1 Variables

A variable is a name that refers to a value. Python is dynamically typed — you do not declare the type explicitly.

name = "Ada"
age = 36
height = 1.68
is_student = True

2.2 Basic Data Types

  • int — whole numbers (42, -7)
  • float — decimal numbers (3.14, -0.5)
  • str — text ("hello", 'world')
  • bool — True or False
  • NoneType — None (represents absence of a value)

2.3 Type Checking & Conversion

Control Flow — Conditionals & Loops

Learning Objectives

  • Write conditional statements with if / elif / else
  • Use for and while loops

3.1 if / elif / else

score = 85
if score >= 90:
    grade = "A"
elif score >= 80:
    grade = "B"
elif score >= 70:
    grade = "C"
else:
    grade = "F"

3.2 for Loops

for i in range(5):
    print(i)          # 0 1 2 3 4

for fruit in ["apple", "banana", "cherry"]:

    print(count)

3.4 break, continue, and else on loops

break exits the loop immediately. continue skips the rest of the current iteration. A loop can also have an else clause that runs only if the loop did not hit a break.

Functions & Scope

Learning Objectives

  • Define and call functions
  • Use positional, keyword, default, *args and **kwargs parameters
  • Understand the LEGB scope rule

4.1 Defining Functions

def greet(name):
    """Return a greeting message."""
    return f"Hello, {name}!"

print(greet("World"))

4.2 Parameters

def power(base, exp=2):
    return base ** exp

def total(*numbers):
    return sum(numbers)

def profile(**info):
    for k, v in info.items():
        print(f"{k}: {v}")

4.3 Scope (LEGB rule)

Python looks up names in this order: Local → Enclosing → Global → Built-in. Use the global and nonlocal keywords when you need to modify variables from outer scopes.

4.4 Lambda Functions

square = lambda x: x * x
print(square(5))   # 25

Chapter Summary

    print("That was not a valid number.")

else:

11.1 What is Django?

Django is a high-level Python web framework that encourages rapid development and clean, pragmatic design. It follows the Model-Template-View (MTV) pattern and includes an ORM, an admin interface, authentication, form handling, and many other batteries-included features.

11.2 Key Design Principles

  • Explicit is better than implicit
  • Loose coupling and high cohesion

Views, URLs & Templates

Learning Objectives

  • Write function-based views
  • Configure URL patterns
  • Create and extend templates

14.1 Function-Based Views

from django.shortcuts import render, get_object_or_404
from .models import Post

def post_list(request):
    posts = Post.objects.filter(is_published=True)
    return render(request, "blog/post_list.html", {"posts": posts})

def post_detail(request, pk):
    post = get_object_or_404(Post, pk=pk)
    return render(request, "blog/post_detail.html", {"post": post})

14.2 URL Configuration

# blog/urls.py
from django.urls import path
from . import views

urlpatterns = [
    path("", views.post_list, name="post_list"),
    path("post/<int:pk>/", views.post_detail, name="post_detail"),
]

Include the app URLs in the project’s main urls.py with path('blog/', include('blog.urls')).

14.3 Templates

<!-- blog/templates/blog/post_list.html -->
{% extends "base.html" %}
{% block content %}
  <h1>Blog Posts</h1>
  {% for post in posts %}
    <h2><a href="{% url 'post_detail' post.pk %}">{{ post.title }}</a></h2>
    <p>{{ post.body|truncatewords:30 }}</p>
  {% empty %}
    <p>No posts yet.</p>
  {% endfor %}
{% endblock %}

14.4 Template Language Essentials

  • {{ variable }} — output a variable
  • {% for %} / {% if %} / {% block %} — tags
  • {{ value|filter }} — filters
  • {% url 'name' %} — reverse URL lookup
  • {% csrf_token %} — required inside POST forms

Chapter Summary

  • Views contain request-handling logic
  • URLs map paths to views
  • Templates render the response HTML

from .models import Post

class PostForm(forms.ModelForm):
    class Meta:
        model = Post
        fields = ["title", "body", "is_published"]

16.2 Handling a Form in a View

from django.shortcuts import render, redirect

def post_create(request):
    if request.method == "POST":
        form = PostForm(request.POST)
        if form.is_valid():
            form.save()
            return redirect("post_list")
    else:
        form = PostForm()
    return render(request, "blog/post_form.html", {"form": form})

Chapter 18

Class-Based Views & Generic Views

Learning Objectives

  • Understand the benefits of class-based views
  • Use common generic views (ListView, DetailView, CreateView, etc.)

18.1 Why Class-Based Views?

Class-based views (CBVs) make it easy to reuse code and follow the DRY principle. Django ships with many generic CBVs for common patterns.

18.2 Common Generic Views

from django.views.generic import ListView, DetailView, CreateView
from django.urls import reverse_lazy
from .models import Post

class PostListView(ListView):
    model = Post
    template_name = "blog/post_list.html"
    context_object_name = "posts"

class PostDetailView(DetailView):
    model = Post

class PostCreateView(CreateView):
    model = Post
    fields = ["title", "body"]
    success_url = reverse_lazy("post_list")

Chapter Summary

  • CBVs reduce boilerplate for standard CRUD operations
  • Generic views cover list, detail, create, update, and delete
